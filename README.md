# BridgeRdp — SOCKS5 и файловый проводник через RDP

Сетевой прокси направляет TCP-соединения **с локальной машины RDP-клиента через целевую машину**:

```text
Локальное приложение → SOCKS5 127.0.0.1:1080 → плагин в mstsc
                    → RDP DVC → BridgeRdp.Agent на целевой машине → сеть
```

Дополнительные входящие порты на целевой машине не нужны. DNS-имена разрешает агент на целевой машине, если приложение передаёт их SOCKS-прокси (например, `socks5h` в curl).

## Быстрый запуск сетевого прокси

Нужны Windows x64, классический `mstsc.exe` и .NET 10 SDK для сборки. Для готовых сборок нужен .NET 10 Runtime x64 на целевой машине и .NET 10 Desktop Runtime x64 на локальной машине (для WinForms Explorer). Плагин загружается в процесс mstsc; поддержка других RDP-клиентов не проверялась.

1. Закрой mstsc и собери комплект:

   ```powershell
   .\scripts\build-proxy.ps1
   ```

2. На локальной машине размести **всю** папку `artifacts\client` в постоянном месте и выполни из неё:

   ```powershell
   .\register-client.ps1
   ```

   Регистрация выполняется в HKCU. Перемещение DLL после регистрации требует повторной регистрации. Скрипт только регистрирует плагин; сборка сама не меняет реестр.

3. Подключись к целевой машине через mstsc. Скопируй туда **всю** папку `artifacts\agent` и запусти внутри RDP-сессии:

   ```powershell
   .\BridgeRdp.Agent.exe
   ```

4. На **локальной** машине настрой приложение на SOCKS5 `127.0.0.1:1080`. Например:

   ```powershell
   curl.exe --proxy socks5h://127.0.0.1:1080 https://example.com
   ```

   Исходящее соединение установит целевая машина. HTTPS проходит как обычный TCP-туннель, без расшифровки TLS.

Для остановки нажми Ctrl+C в агенте или закрой RDP-сессию: локальный порт и соединения освободятся. После переподключения запусти агент заново. Удаление регистрации на локальной машине: `unregister-client.ps1`, затем перезапуск mstsc.

### Параметры и ограничения

- SOCKS5 поддерживает `CONNECT`, IPv4, IPv6 и DNS-имена. `BIND` и UDP/QUIC не поддерживаются; приложениям нужен TCP.
- Слушатель привязан к IPv4 loopback `127.0.0.1`, без аутентификации. Использовать его могут локальные процессы текущей машины. В LAN порт не публикуется.
- До 128 соединений на канал. Данные идут чанками по 32 КиБ; подтверждения записи и чтение по запросу ограничивают буферизацию при медленном получателе.
- Таймаут SOCKS-рукопожатия — 30 секунд, подключения агента к адресу — 20 секунд. Простой установленных TCP-соединений не ограничен.
- Порт задаётся переменной `BRIDGERDP_SOCKS_PORT` в окружении **mstsc**. Для другого порта закрой все процессы mstsc и запусти новый из PowerShell:

  ```powershell
  $env:BRIDGERDP_SOCKS_PORT = '1081'
  mstsc.exe
  ```

  В приложении используй выбранный порт. Агент не меняет порт; сообщение в его консоли приводит стандартный 1080.
- Один активный агент на RDP-сессию. Разные сессии на одной локальной машине должны использовать разные порты и отдельные процессы mstsc с соответствующим окружением.
- Если порт занят или плагин не загрузился, проверь `%TEMP%\BridgeRdp.Client.log` на локальной машине. Перезапусти mstsc после сборки/регистрации. Для работы требуются разрешённые динамические виртуальные каналы в RDP-политиках.

### Проверки

```powershell
dotnet build BridgeRdp.slnx -m:1
dotnet run --project tests/BridgeRdp.Tests --no-build
```

Тесты без сторонних пакетов проверяют SOCKS-рукопожатие, ошибки подключения, кадрирование, восемь параллельных двусторонних TCP-передач, DNS-имена, полузакрытие TCP и очистку при разрыве канала. В тестах DVC заменён транспортом в памяти, TCP-сокеты настоящие, только loopback. Загрузку COM-плагина в mstsc и передачу по настоящему RDP-каналу необходимо отдельно проверить на двух машинах.

Сетевые компоненты: `BridgeRdp.Proxy` (SOCKS5, протокол и TCP-агент), `BridgeRdp.Client/ProxyChannel.cs` (локальная сторона DVC), `BridgeRdp.Agent` (консольное приложение на целевой машине). Используется отдельный канал `BridgeRdp.Proxy`.

## Локальный файловый проводник

`BridgeRdp.Explorer.exe` запускается **на локальной машине RDP-клиента** и показывает диски и папки **целевой машины**. Просмотр, скачивание и загрузка работают через канал `BridgeRdp.Files`, без общих дисков и входящих TCP-портов.

```text
Локальный Explorer → named pipe текущего пользователя → плагин mstsc
                   → RDP DVC → BridgeRdp.Agent → файловая система целевой машины
```

### Запуск

1. Закрой mstsc и собери обновлённый комплект: `.\scripts\build-proxy.ps1`.
2. На локальной машине обнови **всю** папку `artifacts\client`. Если поменялось расположение плагина, повторно выполни `register-client.ps1` из этой папки. Перезапусти mstsc.
3. На целевой машине обнови **всю** папку `artifacts\agent` и запусти `BridgeRdp.Agent.exe` внутри RDP-сессии. По умолчанию он обслуживает одновременно SOCKS5 и файлы.
4. На локальной машине запусти `artifacts\explorer\BridgeRdp.Explorer.exe`. При переносе Explorer копируй всю папку. В окне появятся диски целевой машины.

Если нужны только файлы, запускай агент с `--files-only`: свободный SOCKS-порт не требуется. Для прежнего режима только сетевого прокси доступен `--proxy-only`.

Во всех режимах агент проверяет активность клавиатуры и мыши в своей RDP-сессии. После трёх минут без ввода он слегка сдвигает мышь, чередуя направление; при дальнейшем простое повторяет движение раз в три минуты. Любой ввод пользователя откладывает следующее движение. Механизм работает, пока запущен агент, и останавливается вместе с ним. Принудительные ограничения длительности сессии и политики блокировки Windows могут действовать независимо от этого механизма.

При нестандартном `BRIDGERDP_SOCKS_PORT` в окружении mstsc выбери ту же сессию для Explorer:

```powershell
.\BridgeRdp.Explorer.exe --port 1081
```

Здесь порт служит идентификатором локального файлового канала, отдельного TCP-слушателя для файлов нет. Одновременно к каналу подключается одно окно Explorer. Разные RDP-подключения используют разные значения порта. Плагин и Explorer должны работать от одного Windows-пользователя; named pipe ограничен `CurrentUserOnly`.

### Возможности

- Диски, адресная строка, переход в папку двойным кликом/Enter, вверх по Backspace, история Alt+←, обновление F5.
- **Скачать…** — выбранные файлы и папки с целевой машины в локальную папку, рекурсивно.
- **Загрузить…**, **Загрузить папку…** и перетаскивание локальных файлов/папок в окно — на целевую машину.
- Двойной клик по файлу скачивает временную локальную копию и открывает её программой по умолчанию. Редактирование этой копии не загружается обратно автоматически.
- Создание папок, переименование F2, удаление Del с подтверждением. Удаление рекурсивное, без корзины.
- Сортировка, системные иконки, прогресс и отмена передачи. Каталоги-ссылки пропускаются при рекурсивном копировании, чтобы избежать циклов.

При передаче файл записывается в `.bridgerdp-<guid>.part` рядом с назначением. После успешного завершения он заменяет файл назначения. Существующий файл с тем же именем перезаписывается; отмена до завершения и ошибка чтения сохраняют прежнее содержимое. При аварийном обрыве загрузки на целевой машине может остаться `.part` — его можно удалить. Уже переданные файлы при отмене копирования папки остаются на месте. Копирование не создаёт согласованный снимок файлов, которые другие приложения меняют во время чтения.

После закрытия окна Explorer можно запустить его снова, агент продолжит работать. После обрыва RDP перезапусти агент и нажми «Переподключить» в Explorer. Ошибки плагина: `%TEMP%\BridgeRdp.Client.log` на локальной машине.

### Файловые компоненты и проверки

| Компонент | Назначение |
|---|---|
| `BridgeRdp.Files` | Общий файловый RPC, передача файлов, файловый сервис и кадрирование named pipe |
| `BridgeRdp.Client/FilesChannel.cs` | Мост из локального named pipe в DVC |
| `BridgeRdp.Agent` | Файловые операции с правами пользователя удалённой сессии |
| `BridgeRdp.Explorer` | Локальный интерфейс WinForms |
| `BridgeRdp.Protocol` | Запросы, ответы и JSON/бинарные кадры |

Файл передаётся чанками до 60 КиБ с окном до 32 запросов (1,875 МиБ данных в полёте). Мост в mstsc отправляет запросы конвейером, без ожидания ответа на каждый блок. Агент держит файл открытым между блоками; дескрипторы закрываются при завершении/отмене передачи, отключении Explorer и разрыве канала. Файловый агент выполняет запросы последовательно, чтобы сохранять порядок записи. Максимальный кадр/список каталога — 16 МиБ. Права доступа определяются Windows на целевой машине.

### Прежний проводник в обратном направлении

Сохранён режим просмотра **локальных файлов из удалённой сессии**:

```powershell
# На целевой машине внутри RDP-сессии:
.\BridgeRdp.Explorer.exe --legacy
```

Он использует старый канал `BridgeRdp`. Агент для этого режима не требуется. Старый канал даёт процессам доверенной RDP-сессии доступ к файлам локального пользователя с его правами; новая файловая возможность использует отдельный канал и работает в противоположном направлении.
